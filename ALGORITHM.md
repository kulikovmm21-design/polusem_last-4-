## Постановка задачи

Цель алгоритма — выявление респондентов, демонстрирующих неестественно высокий уровень активности в потоке поисковых запросов.

Под аномалией понимается поведение, характерное для:

* автоматизированных скриптов;
* накруток поисковой активности;
* искусственного увеличения OTS отдельных брендов.

Алгоритм ориентирован исключительно на поиск **завышенного вклада**. Низкие значения активности никогда не являются причиной удаления наблюдений.

---

## Определение аномалии

Первичный анализ выполняется на уровне комбинации:

```text
(SubjectID, researchdate, BrandID, CategoryNameDelivery)
```

При обнаружении хотя бы одного аномального события применяется правило сквозного удаления:

```text
(SubjectID, researchdate)
```

Пара заносится в файл:

```text
output/anomalies.csv
```

и вся активность данного респондента за указанный день исключается из дальнейших расчётов.

---

## Расчёт суточного вклада

Для каждого респондента рассчитывается показатель суточного вклада:

```text
daily_ots = Weight × count_rows
```

где:

| Переменная   | Описание                                         |
| ------------ | ------------------------------------------------ |
| `Weight`     | Статистический вес респондента                   |
| `count_rows` | Количество поисковых запросов за сутки по бренду |

В расчёт включаются только записи, удовлетворяющие условиям:

```text
BrandinDelivery = 1
CategoryNameDelivery != NULL
```

## Двухконтурная модель обнаружения

Основой алгоритма является модифицированный **Robust Z-Score**, построенный на медиане и медианном абсолютном отклонении (MAD).

В отличие от классического Z-Score:

```text
(x - mean) / std
```

робастная версия устойчива к экстремальным выбросам и не позволяет самим аномалиям существенно влиять на границы обнаружения.

---

### Контур крупных брендов

Используется для брендов с достаточным объёмом данных:

```text
N ≥ 10
```

Статистики рассчитываются внутри группы бренда:

```text
median = median(daily_ots)

MAD = median(|daily_ots - median|)
```

---

### Контур редких брендов

Для брендов с малой выборкой:

```text
N < 10
```

локальная оценка MAD становится нестабильной.

В этом случае расчёт автоматически переносится на уровень макрокатегории:

```text
CategoryNameDelivery
```

Формулы остаются аналогичными:

```text
median = median(daily_ots по категории)

MAD = median(|daily_ots - median|)
```

Таким образом редкие бренды сравниваются с типичным поведением внутри своей товарной категории.

---

## Robust Z-Score

Для каждого наблюдения вычисляется показатель:

```text
robust_z =
0.6745 × (daily_ots - median)
--------------------------------
max(MAD, 1e-5)
```

где:

| Компонент | Назначение                                              |
| --------- | ------------------------------------------------------- |
| `0.6745`  | Масштабирование MAD до масштаба стандартного отклонения |
| `MAD`     | Медианное абсолютное отклонение                         |
| `1e-5`    | Защита от деления на ноль                               |

### Защита от нулевого MAD

В небольших однородных группах возможно:

```text
MAD = 0
```

Чтобы избежать ошибки деления на ноль, используется ограничение:

```text
MAD_safe = max(MAD, 1e-5)
```

Это обеспечивает корректность вычислений даже для полностью однородных выборок.

---

## Защита от ложных срабатываний

Высокий вес респондента способен искусственно увеличить значение:

```text
daily_ots
```

даже при единичном запросе.

Для предотвращения ложных удалений вводится дополнительное условие плотности потока:

```text
count_rows ≥ 2
```

Следовательно:

* один случайный запрос никогда не считается аномалией;
* алгоритм реагирует только на повторяющуюся активность.

---

## Обоснование выбора метода

| Требование                 | Реализация                                                             |
| -------------------------- | ---------------------------------------------------------------------- |
| Анализ на уровне брендов   | Расчёт выполняется по BrandID или CategoryNameDelivery                 |
| Интерпретируемость         | Каждое срабатывание сопровождается объяснением в `anomaly_reasons.csv` |
| Порог определяется данными | Используются Median и MAD текущего распределения                       |
| Отсутствие ручной подгонки | Нет искусственных ограничений на долю удаляемых наблюдений             |
| Работа с редкими брендами  | Используется перенос контекста на уровень категории                    |
| Воспроизводимость          | Алгоритм детерминирован и не содержит случайных компонентов            |

---

## Фиксированные параметры модели

| Параметр               | Значение | Назначение                      |
| ---------------------- | -------- | ------------------------------- |
| `ANOMALY_THRESHOLD`    | `3.5`    | Порог Robust Z-Score            |
| `MIN_ROWS_FOR_ANOMALY` | `2`      | Минимальное количество запросов |
| `MIN_BRAND_SAMPLES`    | `10`     | Граница между контурами         |
| `MAD_ZERO_SUBSTITUTE`  | `1e-5`   | Защита от деления на ноль       |

---

## Итоговое правило принятия решения

Статистический критерий:

```text
stat_gate = score > 3.5
```

Критерий плотности потока:

```text
flow_gate = count_rows ≥ 2
```

Финальное решение:

```text
is_anomaly = stat_gate AND flow_gate
```

Иными словами, наблюдение признаётся аномальным только в случае одновременного выполнения статистического и поведенческого критериев.

---

## Итог

Алгоритм представляет собой детерминированную двухконтурную систему обнаружения аномалий на основе робастной статистики. Использование Median, MAD и динамического переключения между уровнями бренда и макрокатегории обеспечивает устойчивость модели к выбросам, малым выборкам и попыткам искусственного смещения границ обнаружения.
