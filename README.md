## Входные данные

В корне проекта должна находиться директория:

```text
data/
```

с исходными файлами в формате `.parquet`.

Особенности работы:

* скрипт автоматически обнаруживает и обрабатывает все Parquet-файлы в директории `data/`;
* при отсутствии входных файлов выполнение завершается ошибкой `FileNotFoundError`.

## Описание алгоритма

Используется двухконтурный робастный алгоритм обнаружения аномальной активности на основе показателя **Robust Z-Score**.

### Этапы обработки

| Этап                   | Описание                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------- |
| Валидация              | Фильтрация по `BrandinDelivery == 1`, очистка пустых категорий, приведение типов данных |
| Агрегация              | Расчёт суточного вклада `daily_ots = Weight × count_rows`                               |
| Контур крупных брендов | Расчёт Median и MAD для брендов с выборкой `N ≥ 10`                                     |
| Контур редких брендов  | Перенос расчётов на уровень `CategoryNameDelivery` для брендов с выборкой `N < 10`      |
| Детектирование         | Поиск аномалий по условию `score > 3.5` и `count_rows ≥ 2`                              |
| Очистка                | Удаление всей активности пары `(SubjectID, researchdate)`                               |

### Критерий аномалии

```text
Robust Z-Score > 3.5
AND
Количество запросов за день ≥ 2
```

Ограничение по числу запросов снижает вероятность ложных срабатываний для респондентов с высоким весом.

Подробное математическое обоснование приведено в файле:

```text

```

## Выходные файлы (`output/`)

| Файл                                      | Назначение                                                    |
| ----------------------------------------- | ------------------------------------------------------------- |
| `output/anomalies.csv`                    | Список пар `SubjectID`, `researchdate`, подлежащих исключению |
| `output/anomaly_reasons.csv`              | Диагностический журнал срабатываний                           |
| `output/plots/total_ots_before_after.png` | Динамика общего OTS до и после очистки                        |
| `output/plots/category_ots_change.png`    | Изменение OTS по макрокатегориям                              |
| `output/plots/daily_anomaly_count.png`    | Количество выявленных нарушителей по дням                     |

## Схема обработки данных

```text
data/*.parquet
      │
      ▼
Фильтрация и очистка
      │
      ▼
Расчёт daily_ots
      │
      ▼
Разделение по объёму выборки
      │
      ├── N ≥ 10 ──► Анализ на уровне бренда
      │
      └── N < 10 ──► Анализ на уровне категории
                      │
                      ▼
           Robust Z-Score > 3.5
           count_rows ≥ 2
                      │
                      ▼
             Выявление аномалий
                      │
                      ▼
      Удаление (SubjectID, researchdate)
                      │
                      ▼
          Формирование отчётности
```
