# Фильтрация аномальной активности респондентов в потоке поисковых запросов

Полусеместровый контроль по задаче выявления аномальной активности респондентов в логах поисковых запросов с использованием робастных статистических методов.

## Входные данные

В корне проекта должна находиться директория:

```text
data/
```

с исходными файлами в формате `.parquet`.

Особенности работы:

* скрипт автоматически обнаруживает и обрабатывает все Parquet-файлы в директории `data/`;
* при отсутствии входных файлов выполнение завершается ошибкой `FileNotFoundError`.

## Описание алгоритма

Используется двухконтурный робастный алгоритм обнаружения аномальной активности на основе показателя **Robust Z-Score**.

### Этапы обработки

| Этап                   | Описание                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------- |
| Валидация              | Фильтрация по `BrandinDelivery == 1`, очистка пустых категорий, приведение типов данных |
| Агрегация              | Расчёт суточного вклада `daily_ots = Weight × count_rows`; при неоднозначном Weight берётся максимальное значение за день |
| Контур крупных брендов | Расчёт Median и MAD для брендов с выборкой `N ≥ 10`                                     |
| Контур редких брендов  | Перенос расчётов на уровень `CategoryNameDelivery` для брендов с выборкой `N < 10`      |
| Детектирование         | Поиск аномалий по условию `score > 4.5` и `count_rows ≥ 2`                              |
| Очистка                | Удаление всей активности пары `(SubjectID, researchdate)`                               |

### Критерий аномалии

```text
Robust Z-Score > 4.5
AND
Количество запросов за день ≥ 2
```

Порог 4.5 соответствует ~99.997% нормального распределения, что минимизирует ложные срабатывания и удаляет только действительно экстремальные выбросы. Ограничение по числу запросов дополнительно защищает от ложных удалений респондентов с высоким статистическим весом при единичном запросе.

Подробное математическое обоснование приведено в файле:

```text

```

## Выходные файлы (`output/`)

| ----------------------------------------- | ------------------------------------------------------------- |

| `output/anomaly_reasons.csv`              | Диагностический журнал срабатываний                           |
| `output/plots/total_ots_before_after.png` | Динамика общего OTS до и после очистки                        |

| `output/plots/daily_anomaly_count.png`    | Количество выявленных нарушителей по дням                     |

## Дополнительная аналитика

Для интерактивного анализа:

```bash
python3 -i "solution_Куликов Валерий Сергеевич_ШЦТ-111.py"
```

После завершения `main()` в сессии доступны глобальные переменные `_df_raw`, `_df_ots`, `_df_clean`, `_anomalies_final`.

### Анализ изменений по категориям и брендовым признакам

```python
аналитика_график_до_после_по_признаку(
    _df_ots,
    _df_clean,
    'CategoryNameDelivery'   # или 'Brand', 'Category1', 'Category2', 'Category3'
)
```

### Анализ изменений по демографии и ресурсам

```python
аналитика_график_до_после_по_признаку_raw(
    _df_raw,
    _df_ots,
    _df_clean,
    'Пол'    # или 'Возраст', 'Регион', 'Федеральный_округ',
             # 'ResourceName', 'ResourceType', 'Platform', 'UseType'
)
```

### Анализ динамики бренда

```python
аналитика_тренд_бренда_до_после(
    _df_ots,
    _df_clean,
    'samsung'   # название бренда
)
```

### Анализ активности конкретного респондента

```python
аналитика_таблица_запросов_респондента(
    _df_raw,
    _anomalies_final['SubjectID'].iloc[0],   # SubjectID аномального респондента
    _anomalies_final['researchdate'].iloc[0] # дата
)
```

## Схема обработки данных

```text
data/*.parquet
      │
      ▼
Фильтрация и очистка
      │
      ▼
Расчёт daily_ots (Weight=max)
      │
      ▼
Разделение по объёму выборки
      │
      ├── N ≥ 10 ──► Анализ на уровне бренда
      │
      └── N < 10 ──► Анализ на уровне категории
                      │
                      ▼
           Robust Z-Score > 4.5
           count_rows ≥ 2
                      │
                      ▼
             Выявление аномалий
                      │
                      ▼
      Удаление (SubjectID, researchdate)
                      │
                      ▼
          Формирование отчётности
```
